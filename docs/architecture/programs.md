# Programs

This document covers the Program screen: its three views, the day chips, the programme sheet and registration.

## The Program screen

`ProgramsModule` (`/programy`, tab `Program`, title `Programy`) is the single Program screen. Its directory, `src/Module/Programs/`, also holds its actions and the pure builders named below where each does its work. Its behaviour is `www/programs.js`, not an inline `<script>`: it used to sit in `{% block header %}`, i.e. in `<head>`, which no screen swap can reach. The file exposes one idempotent `window.pgInit(scope)`; the shell loads it for any event carrying the `programs` feature, the loader calls it by dispatching `screen:shown` on the section it has just made visible, and a server-rendered Program screen wires itself on `DOMContentLoaded` so the screen keeps working even if the loader never runs. Everything the screen shows comes from `ProgramProviderInterface`. When a participant is paired, the module also calls `getParticipant()` and marks their programmes `registered` — that marking is what login changes on the screen, besides the sheet's footer, so keep it working when the screen changes. kissj's session read lists real registrations only, and a preregistered programme (kissj's `isPreregistered`, the internal `preregistered`) belongs to a role, so eventApp cannot tell whose it is: a preregistered programme is **never dimmed** and is in neither Moje nor Domů's `Můj program` (a known limitation until kissj sends the participant's role). Times of day in a range are written one way, `Times::CLOCK` (`G:i`: no leading zero on the hour, an unspaced en dash, `8:00–22:00`) — in the sheet's Kdy, the toast, the list rows, the timeline card's name and Domů's cards; a run over two days names both (`čt 3. 6. 22:00 – pá 4. 6. 1:30`); the hour ruler keeps `08:00`.

## Three views

The screen holds three views of that one data set, in a floating pill above the tab bar (`aria-label="Zobrazení programu"`, in this order): **Přehled** (`far fa-list-alt`), **Harmonogram** (the default, so the now-landing is unchanged) and **Moje** (`far fa-user`).

## Harmonogram

**Harmonogram** (the timeline) is a Gantt grid: rows are the distinct `location` values (`location` is reused as the stage axis — the contract has no `stage` field, and programs with a null location fall into a `Bez lokace` row), columns are hours, one page per **day** holds every section's programmes (key `page-YYYYMMDD`), and it is the one place in the app allowed to scroll horizontally. Overlapping programs in one location are packed into sub-tracks by a greedy interval fit. A programme that runs over several days sits on the page of **every calendar day it overlaps**, each piece clipped to its day (`TimelineBuilder::segments()`, at most `MAX_DRAWN_DAYS`), so no piece can stretch a day's axis; an end at exactly 00:00 belongs to the day before, so 23:45–00:00 stays one card on its evening. Every piece carries the programme id as its `data-key` — unique among siblings, which is all the morph matches on, because a page holds one piece per programme — opens the one sheet, and has the same registered state and label; a label names both days whenever the run spans more than one. The sheet, and with it the deep link, belongs to the start day's page, and the lists list the programme once, under that day.

## Zoom

The hour scale is zoomable: everything on the grid is positioned as `calc(var(--hour-width) * n)`, so setting that one property rescales the time axis and nothing else — never `transform: scaleX()`, which would distort the programme names. `--hour-width` runs between `--hour-width-min` and `--hour-width-max` (40–200px, declared in `www/style.css` next to the property), opens at 80px, and is driven by a −/+ pair at the right end of the timeline's day strip, by a two-finger pinch on the grid (`touch-action: pan-x pan-y` on `.tl-scroll` keeps the browser's own pinch out of it; the viewport meta is deliberately left alone so page zoom still works everywhere) and by ctrl+wheel. Every step recomputes `scrollLeft` so the moment under the anchor — the midpoint between the fingers, or the centre of the visible grid for a button — stays put. The scale is kept in `sessionStorage` under `pgZoom:<slug>`, so paging and view switching preserve it and a fresh visit starts at 80px. Below a threshold the ruler thins its text to every second hour while every hour keeps its mark — the script sets `data-hour-step` on the root from the live scale and `www/style.css` hides `.tl-tick:nth-child(even) .tl-tick-label`, so tick positions never move and the leftmost hour is never blanked. The threshold is the rendered label's width plus 19px, measured on the page rather than hardcoded because themix and Montserrat differ by 6px at 14px/700.

## The now-line and the landing

The day holding **now** carries a current-time line: every timeline page states its axis as two instants, `data-axis-start`/`data-axis-end` (`axisStart`/`axisEnd` in the page view model, `DATE_ATOM` with the offset, the provider's wall-clock read as Europe/Prague whatever the server's zone), so `www/programs.js` places now by subtraction on any phone's zone and formats only the label, through `Intl.DateTimeFormat` with `timeZone: 'Europe/Prague'`. What it writes — `data-now` on the one `.tl-page` whose axis holds now and its inline `--now-offset` in hours — the server never writes, so a morph leaves both alone, and `afterMorph()` re-runs `updateNow()` anyway. The line (`.tl-now`, inside `.tl-inner`, which is positioned for it; z-index 2, so over the cards, under the pinned stage column's 3 and the ruler's 6) and its mark on the ruler (`.tl-now-tick` with its `HH:MM` label, inside `.tl-ticks`) are in `--hour-width` units, so the zoom carries them. It updates every 30 s and on `screen:shown`, `visibilitychange` and a morph. The first plain landing inside the event (no `#section-…-program-…` deep link) opens the timeline on today's page with now a third of the way into the visible hours, even from a copy cached days ago whose server-chosen page is stale. A page's axis runs only from its first programme to its last, so before the day's first or after its last now lies on no axis: the landing then falls back to the page keyed `page-` + today's date (`formatDay()`, built from `Intl.DateTimeFormat.formatToParts` in Europe/Prague, not from a locale's printed order) and opens it without a line and without scrolling. `pgNow()` reads `window.pgClock` (a function returning ms) when set, and a `pg:tick` event on `document` re-runs `updateNow()`; both exist for the browser tests, and `BrowserTestCase::pinClock()` installs the clock over CDP before any page script and removes it after the test.

## Přehled and Moje

**Přehled** and **Moje** are one list component (the Twig macro `dayList(kind, days)`, built by `DayListBuilder::buildDays($programs, $registeredIds, $mineRead)`): Přehled holds every programme (`overview`), Moje only the participant's (`days`), each grouped by **day** like the timeline, each in its own view container (`#pg-view-overview`, `#pg-view-list`; the morph matches keys among siblings, so the two may reuse the day keys and the programme ids). Neither pages: every day is in the document, first to last, under its own **sticky heading**, and the reader scrolls the lot. Each item (`.pl-item`, `data-key` the programme id, `data-start`/`data-end` as `DATE_ATOM` instants from `Times::instant()`) is a start-time column (`.pl-time`), the name as the control that opens the sheet, then `.pl-meta` (`do 12:30 · Žlutý les`), a `Přihlášen` tag (`.pl-tag`) on a registered one — in Přehled on the participant's rows, in Moje on every row — and in Moje the perex. Dimming (`.is-dimmed`, with `opacity` — never a colour, because `www/style.css` may not name one — at a strength that keeps the ink at AA) is Přehled's only among the lists, and the timeline's cards: only when the participant's list was actually read (`mineRead`), and never on a preregistered programme; logged out, or paired while `getParticipant()` failed, nothing is dimmed and Moje shows no `Zatím nemáš přihlášený žádný program.` line (the notice explains), since "not chosen" would be a guess; logged out, Moje is the link `Pro svůj program se přihlas kódem z KissJ.` to Profil. Nor does any view say `Program zatím není k dispozici.` when the list could not be read at all (`programmesUnavailable`).

## Day chips

Each view picks its day from a **strip of day chips**, one per view and separate elements (`.pager[data-pg-pager=<kind>]` for kinds `overview`, `timeline`, `list`, holding `<div class="days" role="group" aria-label="Dny" data-pg-days="<kind>">`, the timeline's with its zoom pair beside it) — no arrows, no day menu, no dialog. Every chip is a `<button class="day-chip" data-key data-pg-page data-pg-kind>`, its `data-key` the day's own key (`page-YYYYMMDD` or `day-YYYYMMDD`) so the morph matches it by key, at least 44 × 44, and the current one carries `aria-current="true"` (the others `"false"`) and wears the `state` fill under `on-state`, as the active tab does; `aria-current` is the reader's, so every chip names it in `data-morph-keep`. On Harmonogram a chip switches the page (`showPage()`); in a list the current chip **follows the scroll** and a tap smooth-scrolls (unless reduced motion is asked for) to that day's start — the list behaviour is built per kind for every `[data-pg-pager]` whose kind has a `.pl-day` list. `markChip(kind, key)` marks the chip and brings it into its strip by setting the strip's own `scrollLeft` — never `scrollIntoView()`, which would move the window too — because a strip wider than the phone scrolls sideways (`overflow-x: auto`, no scrollbar); a strip in a hidden view measures nothing, so the view switch brings its chip round when it is shown. The strip keeps `--pager-height`, so the band below stays where it was.

Nothing of this runs on a scroll event: an `IntersectionObserver` watches the day sections against a band starting one pixel below the strip — one pixel, because a day scrolled to its own start puts its top edge and the previous day's bottom edge on the same line and an observer asked about that line answers "both" — and each crossing costs one coalesced `requestAnimationFrame` that reads no geometry. The day owning the top of that band is the day whose heading is stuck there, so the strip and the heading cannot disagree — which holds only because `.pl-head`'s dock line, `bandTop()` and the observer's `rootMargin` all read the **same three tokens**, `--appbar-height` + `--appbar-inset` + `--pager-height`. Leaving the safe-area inset out of any one of them docks the heading behind the strip on a notched install (34px, measured). The observer fixes its margin at creation, so an inset that changed at runtime would leave the band stale until it is rebuilt; nothing does that yet. `.pl-day:last-child` carries a `min-height` of the reading band, or the last day could never dock under the strip and its chip would land short of it.

## Now in Moje, scroll and perex

In Moje `updateNow()` marks the list from the reader's clock with a client-owned `data-now`: `running` on every item whose span holds now, and `next` on the first item still to start on the day that is today (a list read the evening before shows nothing). CSS hangs a `probíhá` chip in the running card's top-right corner (`.pl-item[data-now="running"]::after`, on the card rather than in `.pl-time`, so it escapes the time's 0.75 opacity, with `.pl-time` padded to leave it room) and draws the "teď" line with its `teď` chip above the next one; both chips are small fills of `--now` under `--on-action`, the timeline label's pair, AA by construction — never `--now` as ink, since it is the action fill and as text on a pale ground falls to 2.8:1 (`ThemingTest::testTheNowChipsCarryTheirInkAtAA` measures the pair in every set). The list never scrolls to it. The screen's scroll offset is live state like everything else, so leaving a list and coming back lands where the reader was; switching to Harmonogram and back does too, because that view is exactly one screenful and the browser clamps the window's scroll while it is up, so `showView` saves and restores it. A perex is plain text whose `\n`s are meant (`docs/kissj-contract.md`), so `.sheet-perex` and `.pl-perex` are `white-space: pre-line` and the template puts nothing but the escaped text inside them.

## The sheet

Tapping a programme opens its **sheet**: the name, the section as a tonal chip (`.sheet-chip`), `<dl class="sheet-facts">` with `Kdy` and `Kde`, `Tvůj program` on a registered one, the organisers' messages about it (`Oznámení`, each with its `data-sent-at` time), the perex, and a `.sheet-footer` with exactly one child keyed by its state (so a morph from unregister to register replaces the form rather than patching it, and no whitespace inside, or `.sheet-footer:empty` stops matching) from `SheetBuilder::footer()`, in this precedence: not paired → `unpaired`, a link to Profil `Pro přihlašování se přihlas kódem z KissJ`; then the window — `before` `Přihlašování začne 15. 3. 2027 v 18:00`, `after` `Přihlašování skončilo`, `none` `Přihlašování zatím není otevřené` (no trailing period); then, paired and open, `fixed` (nothing) for a preregistered programme, nothing at all while the participant's own list could not be read, else `register` (`Přihlásit se`, `.btn-primary`) or `unregister` (`Odhlásit se z programu`, two-tap `Opravdu odhlásit?`). A window that cannot be read leaves every paired footer empty.

## Registration

**Registration** is a plain form POST — `POST /programy/{id}/prihlasit` (`program-register`) and `/odhlasit` (`program-unregister`) — so the worker's purge-on-write and the loader's "every non-GET is a navigation" keep every screen consistent: `SameOrigin` (else a 403 page), not paired → 403 with `Pro přihlašování se přihlas kódem z KissJ.`, then `register`/`unregister()` with the session token, and a toast left in the session: `Přihlášen: <name>` with `RegistrationWriter::toastLine()` (`Pá 21. 5. · 9:00–12:30 · Žlutý les`: the capitalised short weekday, `j. n.`, the `CLOCK` range, the place when there is one; a run past midnight names its start day only), `Odhlášen: <name>` with `Místo jsme uvolnili`, a refusal's Czech line from `REFUSALS` (an unknown code `Přihlášení se nepodařilo.` or `Odhlášení se nepodařilo.`), an outage (`ProgramUnavailableException`, the stub's `LocalStateException` among them, or `ProgramDataException`) `Přihlášení se teď nedaří, zkus to prosím později.` or `Odhlášení se teď nedaří, zkus to prosím později.`, and a `SessionExpiredException` the logout as everywhere. What a repeated write's refusal does to a success toast still waiting is in `RegistrationWriter`'s docblock. The answer is a 302 to `/programy#section-<sectionId>-program-<id>`, whose full document takes the toast (the toast is `.pg`'s first child, keyed `toast`) and reopens the sheet under it. `www/programs.js` disables the button on submit (enabled again on `pageshow`) and notes the view the write was sent from in `sessionStorage['pgReturn:<slug>']` (`{id, view, at}`), taken once on landing, so the reader comes back to Přehled, Harmonogram or Moje with the sheet open; a deep link without the note (or for another programme, or older than a minute) opens the timeline as before. The `#section-<id>-program-<id>` deep link opens the right sheet, puts the timeline on its page, and parks the personal list on that programme for when the reader switches to it; `#muj-program` opens Moje and `#muj-program-<id>` opens Moje on that programme with its sheet open.

## The sheet as a dialog

An open `.sheet` is a real dialog — the screen's only one: everything outside it goes `inert` — the app bar, the tab bar, the skip link, the sibling screens — except the toast, which paints above the sheet (a higher `z-index`, never over the sheet's own close button) and whose `✕` stays in the sheet's Tab ring, and Tab rings inside the card, because a modal a reader can tab straight out of is not one. The trap remembers exactly which elements it marked, so closing clears its own and nothing else, and it releases *before* the focus returns to the opener, since an inert element cannot take focus. Opening the sheet also pushes a history entry (`{pgOverlay: true}`, replaced rather than stacked when one is already up), so Android's Back closes it instead of leaving the screen with the rest of the app inert, and closing it any other way goes back over that entry once, with `history.scrollRestoration` held at `manual` while an overlay entry is up so the browser does not restore the scroll it saved; an open asked for while a close's `history.back()` is still in flight waits for it. A day chip opens nothing and pushes no entry. Chrome's history-manipulation intervention may let Back skip an entry pushed without a user gesture (the sheet a deep link opens on landing), so the entry is no guarantee; the backstop is that `popstate` on any entry and `screen:hidden` on the Program screen close the sheet and release the trap, which can leave an orphan entry costing one idle Back — accepted. The sheet's elements are looked up on every use rather than held from the first render, and every child of `.pg` carries a `data-key` (`toast`, `notice`, `pager-<kind>`, `tabs`, `sheet`) or an id (the three views), because the morph matches unkeyed siblings by position and once turned a reference to the sheet into the old day panel. There is no favourite, photo, capacity or attendee count. `ScheduleBuilder` does all the grouping in PHP and hands Twig a finished view model; every page and every sheet is rendered into the DOM so the deep link can open a sheet on any of them.

The view model is readonly objects under `src/Module/Programs/View/`, built in two steps that stay two steps. `ScheduleBuilder::buildViewModel()` is pure and returns a `View\Schedule`: the timeline's `TimelinePage`s with their `RulerTick`s and `StageRow`s of `Card`s, the two lists' `Day`s of `ListItem`s, and one `Sheet` per programme, every sheet with no messages and a null footer. `ShowAction` then, only when there is a sheet and in this order, reads the registration window and the messages and replaces each sheet with `Sheet::completed()`, a copy carrying its `SheetMessage`s and its `SheetFooter`, and builds the `View\ProgramsPage` the template is rendered with. `SheetFooter::$state` is a string, because the template compares it with one, and `Card::$offset`, `Card::$span` and `RulerTick::$offset` are floats that Twig prints as PHP does (`2.0` as `2`); nothing formats them.
