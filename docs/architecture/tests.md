## The browser test case

`tests/Browser/BrowserTestCase` starts its own PHP built-in server (`tests/Browser/router.php`, which serves `/__tests__/` from `tests/js/` and hands every other path to `bin/router.php`; `PROGRAM_PROVIDER_<SLUG>=local` pinned for every event in `EventCatalog::slugs()` so a dev `.env` pointing one at kissj never reaches a real API, `PUSH_DB_PATH=var/browser-test.sqlite`, and `SESSION_PATH` and `STUB_STATE_PATH` at 0700 temp dirs of the class's own, removed afterwards, so a run leaves no root-owned `var/sessions` or `var/stub`; `CACHE_PATH` is `tests/bootstrap.php`'s) and drives either a local chromedriver (`PANTHER_CHROME_DRIVER_BINARY` or PATH; CI) or Selenium (`PANTHER_SELENIUM_URL`, with `BROWSER_TEST_HOST`; the compose `test` service). Every test runs at a 412 × 915 phone, but headless Chrome clamps its window to at least 500px, so `--window-size` (`windowSize()`) is not enough: the class overrides the device metrics over CDP (`Emulation.setDeviceMetricsOverride`, the protected `overrideViewport()`, which a test that narrows the page puts back) and passes `--hide-scrollbars`, so `clientWidth` is the viewport's. The lane is **hermetic**: `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE <test host>` makes every third-party host (the Maps iframe, Chrome's own Google traffic) fail at once, because one request that hangs after it was sent holds the load event, Chrome has no timeout for that, and the WebDriver navigate then dies on php-webdriver's 180 s curl timeout — the intermittent first-page stall the lane used to have. Fonts and icons are self-hosted, so the screens render with their real typefaces and icons there; only the map's iframe is missing. `pair()` pairs as a reader does (Profil, the start, the page's own poll) and ends on the landing: it waits up to 20 s for a loaded `/<slug>/programy…` whose `push-identity` meta is set; a browser already paired stays on Profil, and a caller that needs Profil afterwards visits it. `noInstallOffers()` registers, like `coldScreens()` (`window.appWarm = false`) and removed after the test with the pinned clocks, a CDP new-document script that stops Chrome's trusted `beforeinstallprompt` in the capture phase, so only a test's own (untrusted) offers reach `shell/install.js`. `freezeServerClock($atom)` restarts the server with its clock frozen there for the rest of the test (`tearDown()` puts it back on the real clock and drops the browser's cookies, whose session carries the frozen times): libfaketime is preloaded into the PHP server (`LD_PRELOAD`, `FAKETIME` in UTC under `TZ=UTC`, so libc needs no zone data), as `bin/gate.php` serves the app, and the server's own `data-fetched-at` on `/obrok27/offline` is read back to prove it took; Chrome keeps the real clock. libfaketime comes from the compose `test` service's image (`docker/test.Dockerfile`, `php:8.5-alpine` plus `apk add libfaketime`) and from CI's `apt-get install libfaketime`; without it the test skips, or fails under `PANTHER_NO_SKIP=1`. An edit to `docker/test.Dockerfile` takes effect only after `docker compose --profile browser build test`. The frozen instant is a static every browser class shares, so `tearDown()` thaws in a `finally` behind `unpinClock()` and `tearDownAfterClass()` clears it as well: a later class never starts its server on a frozen clock. `bin/baseline.php` subclasses it (its `mode()`, `localClient()`, `remoteClient()` and `removeDatabase()` are protected for that) and so shoots the baseline under the same rule, in the real look.

## The JavaScript unit tests

The pure logic of the scripts is tested in Chrome, without Node. The test files are `tests/js/*.test.js`, and each one imports the module it tests by its unversioned URL (`/js/home/nextup.js`), which the test server serves from `www/js/`. `tests/js/harness.js` gives them `test(name, fn)` and `assert.equal`, `deepEqual`, `ok` and `throws`; a test may return a promise. `tests/js/runner.html` loads `tests/js/all.js`, which imports every test file and then calls `finish()`, and the harness puts the outcome on `window.__results`. `JsUnitTest` opens the runner and fails on any failed test, and on a test file that could not be loaded. A test that needs DOM builds its own nodes and removes them again (the two-root test in `programs.test.js` does this, and so does the one next to it that proves the Program screen's links are intercepted: a plain click and Space on a pill link act and leave the click default-prevented, a modified click is left to the browser; ## Text assertions

Some functional tests read a script as text, because no PHP test can run it. Each such assertion is one of two kinds, and the kind decides what happens to it when the code changes:

- **A contract** is a string that must agree with something outside the script: a header, a route, a storage key, a message type, a selector or attribute the templates render, a Czech sentence the spec fixes, an event name, or the value of a named constant (`TOAST_MS = 6000`, `LOAD_TIMEOUT = 8000`, `READY_TIMEOUT = 10000`, `NEXT_SHOWN = 3`). It stays a text assertion. It points at the module that holds the string, and it is respelled only as far as the code forces.
- **A spelling** asserts that logic is written a certain way, because it could not be run. Prefer a JavaScript unit test of that logic, or a Chrome test that proves the behaviour. A spelling is never dropped for nothing: if neither kind of test proves what it guards, it stays a text assertion.

Three mechanical rules apply to both kinds. An event name is spelled only in `events.js`, so an assertion that a module listens for one becomes two: the module calls the helper (`onScreenLoading(`), and `events.js` holds the name. A negative assertion follows the code it guards when that code moves to another module. A count of files or tags is derived from `ScriptVersion::files()` and `Modules::scripts()`, never written as a literal number.
