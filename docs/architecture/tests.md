## The browser test case

`tests/Browser/BrowserTestCase` starts its own PHP built-in server (`tests/Browser/router.php`, which serves `/__tests__/` from `tests/js/` and hands every other path to `bin/router.php`; `PROGRAM_PROVIDER_<SLUG>=local` pinned for every event in `EventCatalog::slugs()` so a dev `.env` pointing one at kissj never reaches a real API, `PUSH_DB_PATH=var/browser-test.sqlite`, and `SESSION_PATH` and `STUB_STATE_PATH` at 0700 temp dirs of the class's own, removed afterwards, so a run leaves no root-owned `var/sessions` or `var/stub`; `CACHE_PATH` is `tests/bootstrap.php`'s) and drives either a local chromedriver (`PANTHER_CHROME_DRIVER_BINARY` or PATH; CI) or Selenium (`PANTHER_SELENIUM_URL`, with `BROWSER_TEST_HOST`; the compose `test` service). Every test runs at a 412 × 915 phone, but headless Chrome clamps its window to at least 500px, so `--window-size` (`windowSize()`) is not enough: the class overrides the device metrics over CDP (`Emulation.setDeviceMetricsOverride`, the protected `overrideViewport()`, which a test that narrows the page puts back) and passes `--hide-scrollbars`, so `clientWidth` is the viewport's. The lane is **hermetic**: `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE <test host>` makes every third-party host (the Maps iframe, Chrome's own Google traffic) fail at once, because one request that hangs after it was sent holds the load event, Chrome has no timeout for that, and the WebDriver navigate then dies on php-webdriver's 180 s curl timeout — the intermittent first-page stall the lane used to have. Fonts and icons are self-hosted, so the screens render with their real typefaces and icons there; only the map's iframe is missing. `bin/baseline.php` subclasses it (its `mode()`, `localClient()`, `remoteClient()` and `removeDatabase()` are protected for that) and so shoots the baseline under the same rule, in the real look.

## The functional test case

`tests/Functional/AppTestCase::createApp()` boots the real app against event fixtures — either a real event under `events/<slug>/` or a minimal fixture event under `tests/fixtures/events/` (among them `window-before` and `window-open`, whose registration windows lie far in the future or around now, so no assertion depends on a real event's dates) — and returns the real Slim `App`/response. It gives every app an in-memory migrated database (`AppTestCase::memoryDb()`, passed as `\PDO::class`), null loggers, a `SpyPushSender` and a fresh `STUB_STATE_PATH` per test (`CACHE_PATH`, the kissj cache and the scripts' version and graph, is one temp dir per run, set by `tests/bootstrap.php`, handed to every server a test starts and removed at the end; a run that starts without `var/cache` and ends with one exits 1); a test that wants to look inside passes its own (`CountingProgramProvider`, `DelegatingProvider` and `ThrowingProgramProvider` wrap or replace the provider). No test hits a live external API; everything program-related comes from the `local` provider's JSON fixtures.

## The JavaScript unit tests

The pure logic of the scripts is tested in Chrome, without Node. The test files are `tests/js/*.test.js`, and each one imports the module it tests by its unversioned URL (`/js/home/nextup.js`), which the test server serves from `www/js/`. `tests/js/harness.js` gives them `test(name, fn)` and `assert.equal`, `deepEqual`, `ok` and `throws`; a test may return a promise. `tests/js/runner.html` loads `tests/js/all.js`, which imports every test file and then calls `finish()`, and the harness puts the outcome on `window.__results`. `JsUnitTest` opens the runner and fails on any failed test, and on a test file that could not be loaded. Biome formats and lints `tests/js/` like `www/js/`.

To add a test, export the pure function from its module (a function of its arguments, with the DOM, the clock and the storage passed in or read by the caller), write `tests/js/<name>.test.js` and add `import './<name>.test.js';` to `all.js`. `JsUnitTest::testEveryTestFileIsImportedByTheRunner` fails when a file is not listed there. A test that needs DOM builds its own nodes and removes them again (the two-root test in `programs.test.js` does this).

## Text assertions

Some functional tests read a script as text, because no PHP test can run it. Each such assertion is one of two kinds, and the kind decides what happens to it when the code changes:

- **A contract** is a string that must agree with something outside the script: a header, a route, a storage key, a message type, a selector or attribute the templates render, a Czech sentence the spec fixes, an event name, or the value of a named constant (`TOAST_MS = 6000`, `LOAD_TIMEOUT = 8000`, `READY_TIMEOUT = 10000`, `NEXT_SHOWN = 3`). It stays a text assertion. It points at the module that holds the string, and it is respelled only as far as the code forces.
- **A spelling** asserts that logic is written a certain way, because it could not be run. Prefer a JavaScript unit test of that logic, or a Chrome test that proves the behaviour. A spelling is never dropped for nothing: if neither kind of test proves what it guards, it stays a text assertion.

Three mechanical rules apply to both kinds. An event name is spelled only in `events.js`, so an assertion that a module listens for one becomes two: the module calls the helper (`onScreenLoading(`), and `events.js` holds the name. A negative assertion follows the code it guards when that code moves to another module. A count of files or tags is derived from `ScriptVersion::files()` and `Modules::scripts()`, never written as a literal number.
