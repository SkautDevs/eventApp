# Theming

This document covers how an event gets its look: the colour palette and semantic roles, light and dark sets, the theme map and fonts, and the logos per surface.

## Colours, assets and the event stylesheet

Theming: each event's `config.php` has a `colors` map (e.g. `base`, `darker`, `primary`, `text`, `text-invert`, and the optional `nav-active`) and an `assets` map (logo/favicon paths under `www/events/<slug>/`). `View\TwigFactory` exposes the whole event config as the `event` Twig global; `_layout.twig` emits the colors as `--color-*` CSS custom properties in an inline `<style>` block, and the core stylesheets under `www/css/` consume them (`var(--color-base)`, etc.) — colour lives in the config, never in a stylesheet. An event may add one optional stylesheet for its non-colour look (shapes, type) as `assets.stylesheet`, a path under `www/`: `_layout.twig` links it through `asset_version()` right after `css/motion.css`, the last core sheet, `Precache` lists its versioned URL, and `ThemingTest` enforces that it names no colour literal, reads only `var(--role-…)`/`var(--theme-…)` with a fallback, and that every role an event declares is read by the core sheets or by that sheet. A rule there must never alter another event, and it must not give `<main>` a stacking context. `EventConfig::REQUIRED_COLORS` is checked at boot, so a half-themed event fails to start rather than rendering with unset properties. No core sheet under `www/css/` may name a colour itself; `ThemingTest::testCoreStylesheetHasNoColorLiterals` enforces that. Type is a seven-step `rem` scale in `:root` (`--fs-2xs` 11 … `--fs-2xl` 24 at a 16px root); two kinds of rule stay in px and `ThemingTest` names them: the chrome glyphs of the fixed-height bars and of the instrument controls (the timeline's zoom pair, the plan's `.plan-zoom-btn` floating on it), whose boxes are measured in pixels — `www/js/programs/` reads the bars' heights as plain pixel numbers — and the timeline grid's type (`.tl-tick`, `.tl-now-label`, `.tl-stage`, `.tl-card`), whose geometry is frozen. The focus ring is one global two-tone `:focus-visible` rule in the ground pair (`--on-ground` outline, `--ground` halo); `.tabs-tab`, `.tl-card`, `.sheet-close` and `.day-chip` (its strip scrolls sideways, so it clips) move it inside their clipping box; the sheet's dialog container and the screen section (programmatic focus targets) draw none.

## The core stylesheets

The app's own CSS is nine files under `www/css/`. `base.css` holds the `@font-face` rules, the tokens and the role definitions in `:root`, the type scale, assistive text, the focus ring, the bare-button reset and the typography. `shell.css` holds the frame every screen shares: the app bar, the screen stack, the error and offline pages, the network banner and the toast, the tab bar, links, buttons and fields, the notifications card's button and status lines, the notification card, `.empty` and the docked view switcher. Each screen module has its own sheet: `info.css`, `home.css`, `profile.css`, `map.css`, `programs.css` and `admin.css`. `motion.css` holds the one reduced-motion block. Each module names its sheet through `ModuleInterface::stylesheet()` (Push and Handbook have none), and `Module\Modules::sheets()` gives the one link order: `css/base.css`, then the registered modules' sheets in `ModuleRegistry::ORDER` (shell, info, home, profile, map, programs, admin), then `css/motion.css`. `_layout.twig` links them in that order, each through `asset_version()`, and the event's own sheet follows them; `Precache` lists the same files. An event links only the sheets of the modules it registers, all of them on every page, because every screen lives in the one document: korbo26 links no `map.css`.

That order follows the order the sections had in the one `style.css` this replaced, so few rules changed place relative to each other, and a later rule still wins where two of equal specificity meet. A rule lives in the sheet of the module whose template prints its class, not under the header it once sat under, and a rule that several modules print lives in `shell.css`, because a module's sheet is absent on an event without that module. The `.link-card` family is Domů's and sits in `home.css` as one block: Domů's sign-in card matches both `.pair-card` and `.link-card`, which set `align-items` and `gap` differently, and `.link-card` wins only by coming later; inside the block, `.link-card:visited` keeps its place before `.link-card.is-highlight`.

Some rules must stay whole, one rule in one file, because a test reads them as one: the button reset (`.day-chip, .pager-zoom-btn, .tabs-tab, .pl-open`) in `base.css` (`ThemingTest::testTheButtonResetIsSaidOnce`), and `.btn, .btn:visited, .highlight, .highlight:visited` in `shell.css` (`ProgramsTest`). Each `--fs-*` step, the bare `:focus-visible` rule and the `--signature` definition are defined once across all nine files. The `--screen-height` declaration in `base.css` stays on one line under a `biome-ignore format` comment: Chrome keeps an unregistered custom property's text as written, line breaks included, so a wrapped value would change its computed value. `motion.css` is linked last and holds nothing but the reduced-motion block, kept as one block: `ThemingTest::testTheFocusRingIsOneGlobalRule` holds that nothing from `@media (prefers-reduced-motion: no-preference)` on draws an outline or a box shadow. The tests read the nine files as one text, concatenated in link order, through `Tests\CoreStylesheet::read()`. A comment at the head of a sheet names no colour, because `ThemingTest` reads comments too.

## The theme map and fonts

Next to `colors` sits an optional `theme` map (`EventConfig::$theme`, always an array) for the look-and-feel that is not colour — `font`, `font-display`, `font-display-weight`, `radius`/`radius-pill`/`radius-sheet`/`radius-card`, and `motion`. It is emitted as `--theme-*` in the same inline `<style>` block. There is no `font-url` any more: **every font and the icon font are self-hosted**. The `@font-face` rules for themix (400, 700), skautbold, Montserrat (400 to 900; latin and latin-ext, Google's v31 variable files with Google's `unicode-range`, so 800 is a real weight), and navigamus27's Seatren and Luciao Sans (one regular weight each, licensed for the event) live at the top of `www/css/base.css`, one woff2 `src` each, the files under `www/fonts/<family>/`; Font Awesome Free 5.8.1 is `www/vendor/fontawesome-free-5.8.1/` (its `all.min.css` byte-for-byte with its licence header, the three `.woff2` files it names, `LICENSE.txt`), linked by `_layout.twig` as `/vendor/fontawesome-free-5.8.1/css/all.min.css`. So `theme.font` may name only a family `www/css/base.css` declares (or a system font). `EventConfig::fontFamilies()` is what the event renders with — the first family of `theme.font` and `theme.font-display`, quotes stripped, or `themix`/`skautbold` where unset, plus `Font Awesome` always — and `App\Http\Fonts` is the plain table family → web paths that `Precache` puts into the offline set; `Tests\Unit\FontsTest` keeps that table, the `@font-face` rules and Font Awesome's own `url()`s in step.

## Semantic roles

Colour is **semantic roles**, not palette keys. No rule under `www/css/` names a `--color-*` any more; every one reads a role, and the role definitions in `:root` are the only place the palette is touched (`ThemingTest::testNoRuleInTheStylesheetNamesAPaletteKey` enforces exactly that). The rule that keeps the system honest is **one colour, one role** — if an event's green is `state`, green is not also a ground, a surface or a piece of chrome. The set is sized for a 60:30:10 budget: `ground`/`on-ground` with `surface`/`on-surface` as its one block tier (60), `structure`/`on-structure` for the bars, the sheet, the buttons, the toast and the timeline's cards (30), and `action`/`on-action`/`action-link` plus `tonal`/`on-tonal` and `state`/`on-state` sharing the 10, with `edge`, `edge-width`, `heading`, `emphasis` and `scrim` in support, and `now` — the timeline's current-time line and its label, under `on-action` ink — falling back to `action`. `structure` defaults to `--color-darker` rather than `--color-base`: it is the one role that is a filled ground under inverted type at body size, and obrok19's base carries `--color-text-invert` at 3.85:1 where its darker green reaches 6.84:1. Three scopes **rebind** the core roles rather than adding names: a text field, `.sheet-card` and `.tl-scroll` are each their own little surface with their own structure on it, so the grid's cards are simply `structure` in the grid's scope. The rebinding sits on `.tl-scroll` and not on `.pg` because custom properties inherit — on `.pg` it would also reach the day strips and the view tabs.

## Light and dark

**Light mode is light and dark mode is dark, all the way through.** `structure` grounds every bar, sheet and card, so in a light set it is the palest thing on the screen and in a dark set the darkest; a filled near-black app bar in light mode is the "black element in the light mode" the system exists to prevent, and a lifted mid-grey card at night is the same mistake upside down (`ThemingTest::testTheLargeFilledAreasFollowTheMode` measures the relative luminance of every role that names a large fill and holds each mode to its own end of the ramp). Two things follow. First, an accent can only be **ink or a small area filled under dark ink**, never a large fill: obrok27's `#e0ff00` is 1.01:1 on its pale ground and obrok19's `#2a9272` is 3.49:1, so the **active tab is filled with the event's colour and carries `on-state`** (15.4:1 and 4.8:1 under near-black ink) rather than tinted type — the fill is the whole tab, not a chip behind the glyph, because tinted type at those ratios is the regression this rule exists to prevent — and `state` has one shape in both modes; the **app bar, the current day chip (`.day-chip[aria-current="true"]`, under `on-state` like the active tab) and the `Zapsáno` tag (`.pl-tag`, a small fill carrying the ground's hairline) are the only other surfaces filled with `state`**, and everything on the app bar — which carries only the title — therefore takes `on-state` too, because that fill does not flip with the mode while `on-structure` does (it used to take `on-structure`, which put obrok19's body grey on green at 2.56:1); the Profil tab's avatar (`.tab-avatar`, the paired reader's initials in a ring of `currentColor`) takes the tab's own pair, as the glyphs do: `on-structure` on the bar, `on-state` on the active tab; a place's marker on Místa's plan (`.plan-marker`) is a small fill of **`action` ringed in `on-action`**, which tells it apart on a drawing whose colours are anything, and its label (`.plan-marker-label`) is **`structure` under `on-structure`** with the `edge` hairline, like the plan's zoom pair ([map.md](map.md)); the gallery's dots in a programme's sheet are the sheet's own ink, `on-surface` as `.sheet-card` rebinds it, unselected at 40 % opacity ([programs.md](programs.md)); a secondary `.btn`, a `.highlight` link CTA and a `.notice` are **`tonal`** — the accent washed almost all the way into the ground, carrying the accent itself at full strength as ink. `.btn-primary` is unchanged in kind, a filled accent under inverted ink. Second, separation cannot come from a tone step alone, because content scrolls under a bar of very nearly its own colour, so **every bar, sheet and card also carries a hairline, in both modes** — `--edge-width`, still 0 for an event that declares nothing. Light hairlines are neutral and dark ones keep the accent tint; each is meant to clear 3:1 against both sides of itself, which is what the 1px content-block outlines replaced the old 4px frames for (obrok27's dark `edge` does not yet, about 1.8:1 on its ground, until its new palette).

## The identity role

One role sits beside `structure` rather than inside it: `signature`/`on-signature`, **structure that carries the identity**. It behaves like structure — a filled band of chrome with type on it — but its value is a quiet cast of the event's own colour, and the **hour ruler is its only use in the app**; painting a second surface with it would return the screen to the state where nothing could read as an accent (`ThemingTest::testTheIdentityRoleIsUsedByTheHourRulerAndNothingElse` holds it to one). It is deliberately *not* the accent at full strength: a saturated slab is the loudest thing on a light screen and a lit panel at night, and the ruler is chrome. The stage column has its own pair (`stage`/`on-stage`) in the grid's scope because the card and the column want different tones out of the same tier — the card separates from the grid by a step plus its hairline, the column is a band behind bold names — but its value is a **plain neutral in both modes**, because a hue on the largest block of the screen is how accents stop reading. Both pairs fall back to the grid's own `structure`, so an event that declares neither renders exactly as it did. The registered card has a pair of its own in the same scope: `registered-bg` (with `registered-line`/`registered-width`) and its ink **`on-registered`** (`--reg-fg`, falling back to `on-structure`), because on an accent fill the grid's card ink can fall far below AA (navigamus27's light set was 2.0:1); every kissj-design event names it in both sets. korbo26's dark set, likewise, carries a lighter orange (`#f08a3c`) as its `action-link`, `heading` and `emphasis` ink, its fill colour `#dd6700` being 4.39:1 on the dark surface.

## Fallbacks and the hand-authored sets

Every role falls back to exactly the expression its rules used before roles existed, and those **built-in fallbacks are frozen** — they are the pre-round-10 look, dark chrome and all, and the fixture events under `tests/fixtures/events/` are what still exercise them (`testEveryRoleFallsBackToThePalette`, `testStructureDefaultsToThePalettesDeeperTone`). No shipped event uses them: **obrok19 hand-authors a `light` set of its own** and is no longer the frozen control — its tab bar is white, its green fills the app bar, the active tab and the registered programmes, its red is `action`, and `docs/baseline/obrok19/` is re-taken by `bin/baseline.php` at the end of every round, so a diff against it is still how a round shows it disturbed nothing. obrok19 stays **light-only**: no `dark` set, no mode control. An event that wants its own colours declares `roles` as two **hand-authored** sets, `light` and `dark` (`EventConfig::$roles`) — accents do not survive mechanical inversion, so changing a colour is deliberately a two-place edit. `_layout.twig` emits light as the base, then the dark set twice: once under `@media (prefers-color-scheme: dark)` scoped to `:root:not([data-mode="light"])` so the device's setting works without JS, and once under `:root[data-mode="dark"]` so an explicit choice wins. The one **inline script in `<head>`**, before the stylesheet link, first adds `js` to the root on every event ([shell-and-loader.md](shell-and-loader.md), "Without JavaScript"), and on a dark-capable event then sets `data-mode` from `localStorage['obrokColorMode']` (global, not per event) or from `prefers-color-scheme` — never the deferred script at the foot of the page, or the reader sees a frame of the wrong theme. The choice is made on **Profil**, logged in or not (the look is the browser's, not the participant's), and only for an event that declares a dark set: a three-way `<fieldset class="mode-control" data-mode-control>` (`Vzhled`: radios `Světlý`, `Tmavý`, `Podle systému`, one `name="mode"`), handled in `www/js/profile/mode.js` by a delegated `change` listener — `Podle systému` removes the stored choice so the device setting rules again — and re-checked from storage on `DOMContentLoaded`, `screen:shown` and `screen:morphed`. The app bar carries no mode toggle.

`EventConfig::$roles` is an `Event\EventRoles`: `light` and `dark`, each a role => value map in the config's own order, because `_layout.twig` emits them into the inline `<style>` in that order, as it does `colors` and `theme`; a set the config does not declare is `[]`, so obrok19's `dark` is empty and it gets no mode control.

## Logos per surface

Colour reaches the **assets** too, because a bar that follows the mode cannot carry one fixed drawing. `assets.menuLogo` is the tab-bar mark and `menuLogoDark` its dark-mode twin (`.mode-light-only`/`.mode-dark-only` swap them), while `menuLogoOnState` is the drawing for a surface filled with `state` — that fill is the event's own colour, so a mark in that same colour disappears on it. Which drawing goes where follows from what the surface is filled with, and **the tab bar and the app bar are not the same kind of surface**: the tab bar is `structure` and flips with the mode, so it takes the mode pair, but the app bar is `state` and does not, so it takes `menuLogoOnState` exactly as the active tab does. `assets.appBarLogo` overrides that for the app bar alone (precedence `appBarLogo`, `menuLogoOnState`, `menuLogo`); the tab bar never reads it. obrok27 declares `appBarLogo` (the white lilie, on its dark bar in both modes), `mainLogo`/`mainLogoDark` (the wordmark) and no `menuLogo`, so the home tab shows the `fa-home` icon; its `bar`/`tabbar` roles fill the two bars and are read only by `www/events/obrok27/style.css`, so both bars stay dark in light mode. navigamus27 does the same with its own `bar`/`on-bar` (kissj's purple band, `#1b0e44` light and `#2b1977` dark, its wavy bottom edge cut inside the bar's box): `appBarLogo` is the N27 mark with white text, `mainLogo`/`mainLogoDark` the full logo (the light one on a white card), and no `menuLogo`. Each asset is optional and the classes are only emitted when the second drawing exists, so an event with one logo keeps showing it everywhere. `mainLogo`/`mainLogoDark` do the same job on Domů. **The photo placeholder** is a logo surface too: under each photo in a programme's sheet, and under each thumbnail on a Přehled or Moje row (and in its frame while the photo loads, or for good when it fails) sits the event's logo on `tonal`, a third of the frame's width (`templates/_photo_mark.twig`, `.photo-mark`). It takes Domů's `mainLogo`, with `mainLogoDark` as the mode pair when both are declared, else the tab bar's `menuLogo`, else nothing, leaving the plain `tonal` frame; see [programs.md](programs.md), "The sheet".

The drawings are `EventConfig::$assets`, an `Event\EventAssets` with one property per asset key: a declared `''` stays `''` and an undeclared one is null, and the templates treat both as none.
