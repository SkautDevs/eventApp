# Program provider

This document covers where programme, section, place, window and participant data come from: the provider interface, its local and kissj sources, and the cache in front of kissj.

## The provider interface

Program/schedule data goes through `App\Program\ProgramProviderInterface`: `getPrograms()` (each with `preregistered`, bool), `getSections()`, `getPlaces()` (the event's `Program\Place`s keyed by id, in the source's order, which for kissj is sorted by name; empty from a source that sends none, such as kissj 3.0), `getRegistrationWindow()` (`Program\RegistrationWindow`, `start`/`end` either possibly null; `state($now)` is `none`, `before`, `open` or `after`, the start inside, the end outside), `getParticipant($sessionToken)` (`Program\Participant`: kissj's participant `id`, the `nickname` or null, and their active registrations as `programmes`), `getParticipantIdsForProgramme($id)`, `startPairing($deviceId)` (`Program\Pairing`: device code, user code, verification URL, expiry, interval; `formattedUserCode()` shows `483291` as `483 291`), `pollPairing($deviceCode)` (`Program\PairingPoll`: a `PairingStatus` — `pending`, `slowDown`, `expired`, `approved` — and, on approval only, the session token and its expiry), `register()`/`unregister($sessionToken, $id)` and `revokeSession($sessionToken)`. Every method may throw `ProgramUnavailableException` (the source did not answer: the app's own type, since Guzzle 8 ties its `TransferException` to a request) or `ProgramDataException` (it answered nonsense) when the source fails; the session calls throw `SessionExpiredException` when the device session is unknown, expired or revoked (which logs the reader out), and the writes `RegistrationRefusedException` with the contract's code (`notPaid`, `closed`, `notFound`, `notPossible`, `wrongRole`, `alreadyRegistered`, `notRegistered`, `conflict`, `full`) when the source says no.

## Programmes and sections

`getPrograms()` returns a list of `Program\Programme`, `getSections()` the `Program\Section`s keyed by id in display order, `getPlaces()` the `Program\Place`s keyed by id, and `Participant::$programmes` is a list of `Programme` too. `Programme` and `Section` are readonly objects whose row form, `fromArray()` and `toArray()`, is exactly the JSON the fixtures (`programs.json`) and the cache entries stored when programmes were arrays, so a file written before the change reads the same after it: `{id, name, section: {id}, start: {date}, end: {date}, lector, location, perex, tools, preregistered}` for a programme, a date being a Prague wall-clock `Y-m-d H:i:s` or `''` for none, and `{id, title, subTitle}` for a section. Contract 3.1 adds two keys at the end of a programme's row, `placeId` (an id of `getPlaces()`) and `images` (a list of `{url, thumbUrl, alt}`, `Program\ProgrammeImage`, in the source's order); `toArray()` spells `placeId` out only when it is not null and `images` only when the list is not empty, so a programme without either has exactly the row of the release before. A place's row is kissj's own `{id, name, lat, lng}` (`Place::toArray()`), with `hasGps()` true when both coordinates are set. A programme's `start` and `end` are `DateTimeImmutable`s in Prague (a date string with an offset of its own is converted), so every time is printed with `format()` and comes out in the event's zone whatever the server's is. `location` is kept as given, untrimmed: the timeline's stage rows, the list rows and the toast line trim it, the sheet prints it as it is.

`fromArray()` is lenient because the screens were: a missing or irregular field takes the value they used to fall back to (no name `''`, no section `0`, no text null, not preregistered), and an empty, missing or unparsable date is null, which `ScheduleBuilder` then keeps off the screen. Only a row without an integer `id` is no programme at all: the local source drops it, and in a cache entry it makes the entry one of the wrong shape, i.e. missing. The 3.1 additions are read just as leniently, so they never fail a list: a `placeId` that is not an integer of at least 1 is null, and `images` that are not a list are none, a list's element without non-empty string `url` and `thumbUrl` being dropped and an `alt` that is no string read as `''`. `Programme`'s and `Section`'s docblocks give each field's rule.

Places are mapped by `App\Program\Places::fromKissj()`, from kissj's `places` or the stub's `places.json`, and never fail either: anything but a list is no places, a record without a positive integer `id` or a non-empty string `name` is skipped, and of two records with one id the first wins. Coordinates count only as a pair of numbers (a JSON integer such as `50` too, read as `50.0`; never a string or a bool) with `-90 ≤ lat ≤ 90` and `-180 ≤ lng ≤ 180`, edges included; otherwise both are null and the place has no GPS. Nothing sorts the places: they keep the source's order.

## The local source

`LocalProgramProvider` (the `local` source) reads `events/<slug>/fixtures/programs.json`, `sections.json`, the optional `places.json` (kissj's own `places` list, like `sections.json`; no file, no places), `registered.json` (participant id → programme ids), the optional `participants.json` (participant id → nickname) and the optional `registration.json` (the window) — no network calls, safe for dev and tests. It approves a pairing on the first poll as the first participant of `registered.json` (or `1`), minting a fresh token `stub-<id>-<16 hex>` on every approval, so a logout (which revokes the token) never blocks the next pairing; writes follow kissj's order of checks (session, window, `notFound`, `notPossible`, `alreadyRegistered`/`notRegistered`), and as in kissj a preregistered programme is in nobody's list. Registrations made in the app and revoked tokens live in `<STUB_STATE_PATH>/<slug>.json` (`{"registrations": {...}, "revoked": [...]}`), read-changed-written under one `LOCK_EX`, so two workers writing at once (a double tap) see each other's write; a file that is not valid JSON (a half-written one caught mid-write) counts as empty, and a state file that cannot be created, locked or written is `Program\LocalStateException` — a `ProgramUnavailableException`, so callers treat it as an outage.

**The demo events' fixtures.** obrok27, navigamus27, korbo26 and miquik26 serve fixtures generated from the kissj-shaped responses under `tests/fixtures/kissj/<slug>/` by `bin/kissj-fixtures.php`, through the real `KissjProgramProvider`: `places.json` is the list's own `places` value (`[]` without one), and `programs.json` spells out `placeId` only when it is set and `images` only when there are any, each photo URL root-relative (`/events/<slug>/demo/<name>.webp` and `<name>-thumb.webp`, the converter's fake origin `https://kissj.example` stripped), so the files under `www/events/<slug>/demo/` are served by the app itself. The places, the `placeId`s and the photos are demo values from a committed overlay, `tests/fixtures/kissj/<slug>/demo.json` (`places`: a programme's `place` string to `{lat, lng}` or null; `images`: a programme id to photo names): `bin/demo-media.php <slug>` (`Tools\Fixtures\DemoMedia`) rewrites `programme-list.json` and `participant.json` into contract 3.1 from it — every distinct non-empty `place` string a place, ids from 1 in `strcmp` order of the names, `places` right after `sections`, the participant's programmes with the same fields and its body with no `places`, a name or id the list lacks an error — and draws the photos that are missing (`Tools\Fixtures\DemoPhoto`: flat shapes seeded by the name, 1200 × 800 WebP q80 plus a 256 × 256 centred thumb at q75, both together at most 60 KB; it needs GD, see its header). The local-only converters still write 3.0, so after one runs the order is converter → `bin/demo-media.php` → `bin/kissj-fixtures.php` (korbo26 with `--clamp-all-day=08:00-22:00`); a photo is never redrawn, and a changed one ships under a new name.

## The kissj source

`KissjProgramProvider` (Guzzle-based) talks to the real kissj programme API (kissj's API contract **3.1**): the list with its places, the device pairing, the participant behind a device session (sent as `X-Kissj-Device-Session` beside the API key), the two writes and the revoke, and validates everything that arrives. A `401` with an empty body on a call that carries a device session is `SessionExpiredException` (a 401 with a body is a rejected API key, an outage, or every reader would be logged out); a `400` with the contract's `{"error": code}` on a write is `RegistrationRefusedException`; every other non-200, and a kissj that never answers, is a `KissjTransferException`. `PROGRAM_PROVIDER_<SLUG>` is required for every event and names the source: `local` (the stub, the event's fixture files) or the http(s) root URL of a kissj instance (`KissjProgramProvider`, which then also requires `KISSJ_API_KEY_<SLUG>`); `Environment::programSource()` checks it before the container is built; its docblock says what stops an event from booting and how the tests pin `local`. The URL must be the address a reader's browser can open, because kissj builds the links it hands out (the pairing's verification URL) from it. Events of one deployment may read different kissj instances; the key is sent as `Authorization: Bearer` on every request and is what tells kissj which event is asking, so no event slug is configured anywhere. Locally the events are `local`; the deployed instance reads kissj staging for now (`obrok19`, which kissj does not have, stays `local`), which needs kissj to implement contract 3.0.

The 3.0 fields are validated strictly and the 3.1 additions leniently, so a kissj that still answers 3.0 reads exactly as before, with no places and no photos. The list's `places` becomes `getPlaces()` through `Places::fromKissj()` (above); a missing key is no places, and a value that is not a list is no places plus the warning `kissj.places-invalid`. A programme's `placeId` is an integer of at least 1 or null, and its `images` go through `ProgrammeImage::fromArray()`, in the list and in the participant read alike. A photo is kept only when its `url` and its `thumbUrl` are both absolute URLs on the provider's own origin, `Environment::programOrigin()` of `PROGRAM_PROVIDER_<SLUG>` (scheme, host and port, compared exactly once the scheme's default port is dropped on both sides, so `https://kissj.example:443/…` is on `https://kissj.example` and the other way round, as a browser's `URL.origin` spells it for the CSP and the worker; a URL with credentials, a backslash or whitespace has none), which `Container\Definitions` passes in as `origin`, because Guzzle's `base_uri` cannot be read back. With an https kissj that means https only; a dev kissj on `http://localhost:…` keeps its own http photos. The photos left out are counted, and each read that left any out logs one warning, `kissj.images-dropped`, with `dropped` (the count) and `origin` (the first one's scheme, host and port, or `invalid`), never a URL or a token. The provider logs to the container's `LoggerInterface`, whose warnings reach Sentry.

## Sections

The provider also supplies the programme **sections** through `getSections()` — id, title, display order and the optional `subTitle` — from the `sections` of kissj's list response, or from the stub's `fixtures/sections.json`, which is that same list in kissj's shape (`App\Program\Sections` maps both). The event config carries no `sections` key.

## The cache

`Container\Definitions` wraps the kissj provider — never the stub, whose fixture files already are a local copy — in `Program\CachingProgramProvider`, backed by `Cache\FileCache` under `var/cache/<slug>/`: one JSON file per entry, `{"fetchedAt": "<DATE_ATOM>", "data": …}`, written to a temp file and renamed over the old one; the entries are `list` (`{sections, programmes, registration, places}` from one list response, `places` as `Place::toArray()` rows in order; an entry written before the places, without the key, stays usable and gives no places, so a stale copy served during an outage still shows the programme, and a `places` that is there but no list of rows makes the entry one of the wrong shape) and `session-<first 32 hex of sha256(token)>` (`CachingProgramProvider::sessionKey()`: one device session's `{id, nickname, programmes}` — the token is a secret and is in no filename). An entry younger than `PROGRAM_CACHE_TTL` seconds (instance-wide, `Environment::programCacheTtl()`, whole seconds, default 300 for anything else; `0` always refetches) is served without asking kissj; an older or missing one is fetched and rewritten; an expired one is served **however old** when kissj throws `ProgramUnavailableException` or `ProgramDataException` (stale-if-error), and the failure goes to `Collector::collect()` instead of the reader. Only a missing entry lets kissj's trouble reach the modules' notices. `SessionExpiredException` is an answer, not an outage: the entry is deleted and the exception rethrown — but only once it is asked, so a fresh `session-…` entry keeps a device kissj has since revoked marked for up to the TTL. The pairing calls, the revoke and `getParticipantIdsForProgramme()` are never cached; `revokeSession()` deletes the session's entry whatever kissj answers.

## Invalidation on write

A write that succeeds deletes the session's cached entry, so the redirect after it reads from kissj again; a refusal that shows the cached participant or list is out of date deletes that entry too, and an outage keeps it. How a read already under way is kept from storing the answer from before the write is in `Program\CachingProgramProvider`'s docblock.

## Within and across requests

Within a request the decorator memoises every read and asks kissj at most once after a failure; across requests it keeps kissj from being asked by every request at once with a lock per entry, a 60 s breaker and one report per 5 minutes. `Program\CachingProgramProvider`'s docblock has the rules, and every read updates the request-scoped `Program\Freshness`.
