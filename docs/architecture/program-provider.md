# Program provider

This document covers where programme, section, window and participant data come from: the provider interface, its local and kissj sources, and the cache in front of kissj.

## The provider interface

Program/schedule data goes through `App\Program\ProgramProviderInterface`: `getPrograms()` (each with `preregistered`, bool), `getSections()`, `getRegistrationWindow()` (`Program\RegistrationWindow`, `start`/`end` either possibly null; `state($now)` is `none`, `before`, `open` or `after`, the start inside, the end outside), `getParticipant($sessionToken)` (`Program\Participant`: kissj's participant `id`, the `nickname` or null, and their active registrations as `programmes`), `getParticipantIdsForProgramme($id)`, `startPairing($deviceId)` (`Program\Pairing`: device code, user code, verification URL, expiry, interval; `formattedUserCode()` shows `483291` as `483 291`), `pollPairing($deviceCode)` (`Program\PairingPoll`: a `PairingStatus` — `pending`, `slowDown`, `expired`, `approved` — and, on approval only, the session token and its expiry), `register()`/`unregister($sessionToken, $id)` and `revokeSession($sessionToken)`. Every method may throw `ProgramUnavailableException` (the source did not answer: the app's own type, since Guzzle 8 ties its `TransferException` to a request) or `ProgramDataException` (it answered nonsense) when the source fails; the session calls throw `SessionExpiredException` when the device session is unknown, expired or revoked (which logs the reader out), and the writes `RegistrationRefusedException` with the contract's code (`notPaid`, `closed`, `notFound`, `notPossible`, `wrongRole`, `alreadyRegistered`, `notRegistered`, `conflict`, `full`) when the source says no.

## Programmes and sections

`getPrograms()` returns a list of `Program\Programme`, `getSections()` the `Program\Section`s keyed by id in display order, and `Participant::$programmes` is a list of `Programme` too. Both are readonly objects whose row form, `fromArray()` and `toArray()`, is exactly the JSON the fixtures (`programs.json`) and the cache entries stored when programmes were arrays, so a file written before the change reads the same after it: `{id, name, section: {id}, start: {date}, end: {date}, lector, location, perex, tools, preregistered}` for a programme, a date being a Prague wall-clock `Y-m-d H:i:s` or `''` for none, and `{id, title, subTitle}` for a section. A programme's `start` and `end` are `DateTimeImmutable`s in Prague (a date string with an offset of its own is converted), so every time is printed with `format()` and comes out in the event's zone whatever the server's is. `location` is kept as given, untrimmed: the timeline's stage rows, the list rows and the toast line trim it, the sheet prints it as it is.

`fromArray()` is lenient because the screens were: a missing or irregular field takes the value they used to fall back to (no name `''`, no section `0`, no text null, not preregistered), and an empty, missing or unparsable date is null, which `ScheduleBuilder` then keeps off the screen. Only a row without an integer `id` is no programme at all: the local source drops it, and in a cache entry it makes the entry one of the wrong shape, i.e. missing. `Programme`'s and `Section`'s docblocks give each field's rule.

## The local source

`LocalProgramProvider` (the `local` source) reads `events/<slug>/fixtures/programs.json`, `sections.json`, `registered.json` (participant id → programme ids), the optional `participants.json` (participant id → nickname) and the optional `registration.json` (the window) — no network calls, safe for dev and tests. It approves a pairing on the first poll as the first participant of `registered.json` (or `1`), minting a fresh token `stub-<id>-<16 hex>` on every approval, so a logout (which revokes the token) never blocks the next pairing; writes follow kissj's order of checks (session, window, `notFound`, `notPossible`, `alreadyRegistered`/`notRegistered`), and as in kissj a preregistered programme is in nobody's list. Registrations made in the app and revoked tokens live in `<STUB_STATE_PATH>/<slug>.json` (`{"registrations": {...}, "revoked": [...]}`), read-changed-written under one `LOCK_EX`, so two workers writing at once (a double tap) see each other's write; a file that is not valid JSON (a half-written one caught mid-write) counts as empty, and a state file that cannot be created, locked or written is `Program\LocalStateException` — a `ProgramUnavailableException`, so callers treat it as an outage.

## The kissj source

`KissjProgramProvider` (Guzzle-based) talks to the real kissj programme API (`docs/kissj-contract.md`, contract **3.0**): the list, the device pairing, the participant behind a device session (sent as `X-Kissj-Device-Session` beside the API key), the two writes and the revoke, and validates everything that arrives. A `401` with an empty body on a call that carries a device session is `SessionExpiredException` (a 401 with a body is a rejected API key, an outage, or every reader would be logged out); a `400` with the contract's `{"error": code}` on a write is `RegistrationRefusedException`; every other non-200, and a kissj that never answers, is a `KissjTransferException`. `PROGRAM_PROVIDER_<SLUG>` is required for every event and names the source: `local` (the stub, the event's fixture files) or the http(s) root URL of a kissj instance (`KissjProgramProvider`, which then also requires `KISSJ_API_KEY_<SLUG>`); `Environment::programSource()` checks it before the container is built; its docblock says what stops an event from booting and how the tests pin `local`. The URL must be the address a reader's browser can open, because kissj builds the links it hands out (the pairing's verification URL) from it. Events of one deployment may read different kissj instances; the key is sent as `Authorization: Bearer` on every request and is what tells kissj which event is asking, so no event slug is configured anywhere. Locally the events are `local`; the deployed instance reads kissj staging for now (`obrok19`, which kissj does not have, stays `local`), which needs kissj to implement contract 3.0.

## Sections

The provider also supplies the programme **sections** through `getSections()` — id, title, display order and the optional `subTitle` — from the `sections` of kissj's list response, or from the stub's `fixtures/sections.json`, which is that same list in kissj's shape (`App\Program\Sections` maps both). The event config carries no `sections` key.

## The cache

`Container\Definitions` wraps the kissj provider — never the stub, whose fixture files already are a local copy — in `Program\CachingProgramProvider`, backed by `Cache\FileCache` under `var/cache/<slug>/`: one JSON file per entry, `{"fetchedAt": "<DATE_ATOM>", "data": …}`, written to a temp file and renamed over the old one; the entries are `list` (`{sections, programmes, registration}` from one list response) and `session-<first 32 hex of sha256(token)>` (`CachingProgramProvider::sessionKey()`: one device session's `{id, nickname, programmes}` — the token is a secret and is in no filename). An entry younger than `PROGRAM_CACHE_TTL` seconds (instance-wide, `Environment::programCacheTtl()`, whole seconds, default 300 for anything else; `0` always refetches) is served without asking kissj; an older or missing one is fetched and rewritten; an expired one is served **however old** when kissj throws `ProgramUnavailableException` or `ProgramDataException` (stale-if-error), and the failure goes to `Collector::collect()` instead of the reader. Only a missing entry lets kissj's trouble reach the modules' notices. `SessionExpiredException` is an answer, not an outage: the entry is deleted and the exception rethrown — but only once it is asked, so a fresh `session-…` entry keeps a device kissj has since revoked marked for up to the TTL. The pairing calls, the revoke and `getParticipantIdsForProgramme()` are never cached; `revokeSession()` deletes the session's entry whatever kissj answers.

## Invalidation on write

**A write that succeeds** deletes the session's entry and this request's memo of it, so the very next read — the redirect after the write — asks kissj again; the delete first rewrites the entry's write marker (`written-<key>`, a random value, `WRITTEN_PREFIX`) and then waits for the entry's lock, so a read already under way with kissj's answer from before the write does not store it. A refusal changed nothing and keeps both, except `alreadyRegistered`/`notRegistered` (the cached participant is not what kissj holds: the session entry goes the same way) and `notFound`/`closed`/`notPossible` (the cached list is out of date: the `list` entry goes); an outage keeps the entry.

## Within and across requests

The decorator memoises every resolved read per request (keyed by `Freshness::generation()`) and remembers the inner provider's first failure for the same request, after which an expired entry is served stale and a missing one rethrows that failure without asking kissj again — so an outage costs one timeout per request however many entries a page reads. Across requests three more rules keep kissj from being asked by every request at once, all kept as files beside the entries: **single-flight** — `FileCache::tryLock()` takes a non-blocking `flock` on `<key>.lock`, and while another request holds it a request with an expired entry serves it as `locked` (not marked stale, unless `kissj-down` exists) and one with no entry waits up to 12 s (`$lockWait`; kissj's own timeout is 10 s) via `waitLock()`, then serves the holder's fresh entry, rethrows if the holder failed meanwhile, or fetches itself — a filesystem that cannot lock at all yields a no-op lock rather than "held", and the empty lock files accumulate, one per entry; a **60 s breaker** (`BREAKER_SECONDS`) — a failure writes the `kissj-down` entry and for a minute after it an expired entry is served stale without asking, while a missing one still asks, and a success deletes the marker (one participant's bad answer opens it for the whole event); and **one report per 5 minutes** (`REPORT_SECONDS`, the `kissj-reported` entry, which a success leaves alone, so a flapping kissj is not reported on every flap). An unwritable `var/cache/` makes all three quietly do nothing. An entry of the wrong shape (or a file that is not JSON or has no `fetchedAt`) counts as missing, and a failed write is reported, not thrown. Every read updates the request-scoped `Program\Freshness` (the oldest fetch time served, and whether anything was stale), which the screen middleware resets per request.
